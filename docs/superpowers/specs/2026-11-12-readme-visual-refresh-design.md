# README 可视化重构设计

## 意图

让第一次打开 RSI GraphRAG 的读者在 1–2 分钟内理解：项目解决什么问题、方法如何分成三个阶段、当前实验结论是什么，以及应该去哪里继续核查。README 继续作为研究总入口，实验细节和方法细节仍由现有文档承载。

## 目标

- 在 README 顶部建立清晰的阅读路径：项目定位 → 当前结论 → 方法总览 → 实验与复现。
- 用一张概念总览图帮助非作者读者建立心智模型。
- 将一张复杂的 Mermaid 总流程拆为三个可独立阅读的阶段图，并在每个阶段标出对应代码入口。
- 保留现有数字、链接和结论，避免视觉改造改变研究口径。
- 让 GitHub Markdown 原生渲染即可阅读，不依赖本地服务。

## 非目标

- 不重写实验报告、方法文档或各数据集 README 的研究内容。
- 不改变代码、实验结果和指标定义。
- 不引入需要构建的前端页面或额外运行时依赖。

## 约束

- 生成图片必须作为仓库资产保存，README 不依赖外部临时链接。
- 技术流程优先使用 Mermaid，保证节点、代码和数据流可审阅。
- 图片中的文字尽量少，避免生图模型产生不可读的小字；关键术语在 README 正文中再以文本呈现。
- 现有中文 README 结构和链接保持可用。

## 方案比较

1. **入口重排 + 概念图 + 三段 Mermaid（采用）**：在可读性、审阅性和改动范围之间平衡最好；生图负责解释概念，Mermaid 负责精确表达流程。
2. **只用 Mermaid / SVG**：维护最简单，但第一眼的解释力较弱，不足以改善 README 的“全是文字”问题。
3. **完整拆分 README 与 docs**：长期维护更好，但会改变现有阅读路径，超出本次以“降低阅读门槛”为主的范围。

## 设计

### README 入口

新增“先看这里”区域，包含：

- 一句话定义（Read-Time、Question-Time、RSI Memory 三阶段）。
- 面向审阅者的三个问题：改了什么、证据在哪里、当前结论是什么。
- 关键结论的短卡片，链接到现有实验段落。

### 视觉资产

新增 `docs/assets/rsigraph-rag-overview.png`：

- 横向三段构图：文档阅读 → 图检索 → 问答反馈。
- 以抽象节点、文档卡片和箭头表达关系，不承载密集技术文字。
- 适合作为 README 的概念导图和社交预览式首图。

### 流程图

将现有完整 pipeline 拆为三个 Mermaid 图：

1. Read-Time：文档、OpenIE、分组、Comprehension、验证、图变体。
2. Question-Time：问题、QDM、检索、充分性检查、Reader、答案校验。
3. RSI Memory：反思、清洗、四个 gate、技能记忆、快照选择。

每张图控制在 5–7 个主要节点，并附“对应代码”小表，避免流程图承担全部解释工作。

### 阅读层级

README 采用以下顺序：快速总览 → 当前结论 → 方法总览图 → 分阶段流程 → 实验进度 → 横向对比与问题诊断 → 代码地图与复现。原有细节保留，但通过折叠式提示、短段落和链接降低连续阅读负担。

## 验证标准

- GitHub 风格 Markdown 预览中，首屏能看到项目定位、概念图和当前结论入口。
- Mermaid 语法可被 GitHub 渲染，且三张图没有交叉拥挤的长链路。
- 图片文件存在于仓库，并使用相对路径引用。
- README 中现有章节锚点、实验链接和复现命令仍然可用。
- 使用 Markdown 解析/链接检查和 Mermaid 代码块检查完成基本验证。
