# 成本

原文阅读倍数 = 所有组的 chunk token 之和 / 全库 1,348,035。互斥分组如果覆盖每个 chunk 恰好一次，这个倍数是 1.000。模板按每组 200 token 另计，总倍数 = (原文重复 token + 模板) / 全库。

图：`plots/gold_vs_multiplier.png`、`plots/pairwise_vs_tokens.png`、`plots/overlap_tradeoff.png`。

## 同一预算内能比的方法

| 预算 | 方法 | 原文倍数 | 含模板倍数 | 最大组 token | 完整 gold |
| --- | --- | ---: | ---: | ---: | ---: |
| 1.0× | 向量 + 实体，上限 16 | 1.000 | 1.142 | 4,914 | 313 |
| 1.0× | 顺序切块 16 | 1.000 | 1.108 | 3,737 | 225 |
| 1.0× | 向量 KNN，上限 16 | 1.000 | 1.154 | 5,004 | 209 |
| 1.0× | 向量 + 实体，上限 8 | 1.000 | 1.249 | 2,729 | 262 |
| 1.0× | 纯实体 IDF，上限 8 | 1.000 | 1.449 | 3,292 | 226 |
| 1.2× | 融合组上的有限复制 | 1.200 | — | 组 P95 2,261 | 292 |
| 1.5× | 融合组上的有限复制 | 1.500 | 1.749 | 组 P95 2,712 | 354 |
| 1.5× | 向量组上的有限复制 | 1.500 | — | 组 P95 2,631 | 219 |
| 3.3× | IDF top-2 | 3.286 | — | 组 P95 682 | 252 |
| 15.5× | IDF top-16 | 15.485 | — | 组 P95 3,105 | 544 |

1.2× 的融合复制（292）低于已经在 1.0× 做到的上限 16 融合组（313）。把互斥组做大到 16，比在上限 8 的组上再复制一遍更省，覆盖也更高。1.5× 复制达到 354，比 1.0× 的最好互斥组多 41 道题，原文要多读一半。

Top-2 和 Top-16 的覆盖不能和上表直接比高低。它们用 3.3 倍和 15.5 倍原文换覆盖。按本轮约束，这种重复不计入“低成本分组成功”。

只限制 token、不限制 chunk 数时，4,000 token 的组最大有 60 个 chunk，16,000 token 的组最大 209 个 chunk。短段落会把 token 预算堆成仍然过大的组。容量必须同时限制 chunk 数。

构建时间约 686 秒，主要花在 4,096 维精确 KNN 和若干次 KMeans。峰值内存没有单独采样；向量矩阵本身约 190MB。没有 GPU 推理。
