# 方法

全部超参数写在 `configs/grid.json`，随机种子 20261030。没有用 gold 增加配置。Leiden 使用 modularity、`n_iterations=2`。它仍然有随机性：同一张 KNN 图的两次 Leiden 最大分量差几十个 chunk，这种差距不拿来排名。容量贪心合并是确定的。

无监督筛选在读 gold 之前完成。规则是：原文阅读倍数 ≤ 1.05，chunk 覆盖 ≥ 99%，最大组 ≤ 16 个 chunk 且 ≤ 16,000 token，至少一半 chunk 落在大小 ≥ 2 的组里。在合格方法中，最大化“余弦最近邻落在同一组”的比例。

## 保留的基线 E0

- 原始 NER 连通分量，以及 DF ≤ 10、DF ≤ 50。
- 上一轮的加权 Jaccard ≥ 0.20，pair cap 50。
- IDF top-2 和 top-16，pair cap 50。这是高重复阅读参照，不和 1.0× 方法比胜负。
- 随机分组和语料顺序分组，组大小 4、8、16。

## 本轮新方法

**E7** 对归一化 chunk 向量做 MiniBatchKMeans，目标平均大小 4、8、16。另把目标 8 的结果做递归二分，试图压到 8 或 16。递归二分在 12 轮后仍有大于上限的组，最大分别是 16 和 22，因此不把它们当成已经满足容量约束的方法。

**E8** 全量 average / complete linkage 需要稠密距离矩阵，没有跑。稀疏替代是 E13 的按边权贪心合并。

**E9** 精确余弦 KNN，k = 5、10、20、40，以及 k = 10 的 mutual KNN。边上跑 Leiden，k = 10 另跑分辨率 0.5 和 2.0。

**E10** 候选边是 KNN k = 10 与 DF ≤ 30 的实体对的并集。

```text
idf(e) = ln((N+1)/(df(e)+1))
entity_score = shared_idf / (shared_idf + ln((N+1)/2))
score = α·cosine + β·entity_score + γ·title_score
```

四组权重事先固定：纯向量 (1,0,0)，纯实体 (0,1,0)，融合 (0.5,0.5,0)，再加 title (0.4,0.4,0.2)。Title 相同记 1，否则用标题词 Jaccard。每种权重各跑 Leiden 和容量 8 的贪心；融合另跑容量 16。

**E11** 没有做神经 mention 编码。磁盘上的本地模型只有 NV-Embed-v2，整篇 chunk 向量已经用它算过。对全部 mention 再跑一遍该模型，是一次大规模本地推理，本轮跳过。

**E12** TF-IDF 降到 64 维后做 KNN 和 Leiden，以及容量 8 的贪心。BM25（k1 = 1.5，b = 0.75）用 DF 在 2–80 的词生成候选，再容量 8 贪心。

**E13** 在向量 KNN 上做容量贪心：按边权从高到低合并，超过 chunk 上限或 token 上限就放弃这条边。上限为 4、8、16 个 chunk，以及 4k、8k、16k token。放弃的边保留在统计里，不是把成员悄悄截掉。

**E14** 从三个已经固定的互斥分组出发，按跨组边从强到弱复制 chunk。1.2× 预算最多复制进 2 个组，1.5× 最多 3 个组。复制后组仍须 ≤ 16 chunk 且 ≤ 16,000 token。超出预算的复制被拒绝并计数。

**E15** 在 DF 2–15 的实体上定位 mention 所在句子。31,523 次尝试里 2,042 次找不到，定位率 93.5%。找不到的不猜测。权重是 `idf · (1 − 句子 TF-IDF 余弦)`，再做容量 8 贪心，并与纯 IDF 贪心对照。

**E16** 在 KNN 图上跑了 Louvain、Label Propagation 和 Infomap。METIS 未安装。稠密谱聚类没有跑。

运行约 686 秒，CPU，没有占用 GPU。
