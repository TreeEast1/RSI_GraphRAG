# 结论

在 1.0× 到 1.5× 的索引阅读预算内，无监督分组不能把 MuSiQue 的跨文档支持证据稳定放进同一个小组。不建议进入 Joint Triple Extraction。

Gold 只用于冻结网格之后的比较。无监督规则在读 gold 之前选中的是向量 KNN、每组最多 16 个 chunk。它的完整 gold 同组是 209 / 1,000，低于同样大小的语料顺序切块（225 / 1,000）。

## 十个问题

1. **能否形成较小且有意义的跨文档组？**  
   能形成小的。容量贪心可以把组限制在 4、8 或 16 个 chunk，组 token 最大约 2,700–5,000。组里约 95% 的 chunk 对来自不同 title，所以不是同一篇文章的碎段。有意义的只是局部主题：同一把琴的制作者、同一县的河流、同一套话的军舰。上限 16 的传递合并还会把无关页带进来。

2. **同一 token 预算下，谁的完整 gold 同组最高？**  
   1.0×、最大 16 chunk、最大组不超过 16,000 token 时，是向量加实体的贪心分组，313 / 1,000。1.2× 的复制是 292，反而更低。1.5× 的复制是 354。2.0× 以内没有更高的预置方法。IDF top-16 有 544，但原文阅读是 15.5×，不参与这个比较。

3. **不用共享实体的向量分组，是否明显好于上一轮二部图？**  
   不好于。上一轮二部图的高覆盖来自巨型分量。把向量分组限制到同样可抽取的大小后，上限 16 的完整同组是 209，低于顺序切块的 225，也低于实体 IDF 上限 8 的 226。向量 Leiden 仍有 1,330 chunk 的社区。

4. **实体 IDF 和向量融合有没有增益？**  
   有，但是有限。同一套候选边、上限 8：融合 262，纯实体 205，纯向量 165。上限 16：融合 313，纯向量 209。Title 权重没有再提高（260 对 262）。另一条纯 IDF 贪心是 226，和纯实体同一量级。融合后的 313 仍只比顺序切块多 88 道题。

5. **Leiden、受限 KMeans、层次聚类、图划分哪一种更合适？**  
   在这个语料上，Leiden、Louvain、Infomap、Label Propagation 和 KMeans 都留下数百到上千 chunk 的社区。稠密层次聚类、谱聚类和 METIS 没有跑，原因写在 `METHODS.md`。真正把组切到抽取窗口里的是按边权的容量贪心。递归 KMeans 切分没有稳定压到预设上限。

6. **1.2–1.5× 的少量重复有没有明显改善？**  
   没有明显改善。融合组从上限 8 的 262，到 1.2× 的 292、1.5× 的 354。1.0× 的上限 16 已经有 313。多读 50% 原文，只比最好的互斥组多 41 道题。

7. **跨 title 文档是被合理分在一起，还是仍主要聚集同一篇文章？**  
   主要是跨 title 的主题邻域，不是同一篇文章。融合上限 16 的组内对里，同一 title 只占 4.1%。跨 title gold 对的同组比例是 24.8%。主题邻域包括同一人或同一地名，也包括套话和错误传递。

8. **哪些案例像潜在的跨文档理解？**  
   Stradivari 的三把琴是干净的跨条目连接，事实在每篇里已经写明。Sullivan County 的支流和三艘扫雷舰是重复句式。Molotov 条约与 Malta Summit、Ghost Riders 与 Unchained Melody、Alex O'Loughlin 组里的无关人物，是容量没用完时被弱边带进来的。案例见 `CASE_STUDIES.md`。

9. **如果还要做 Joint Triple Extraction，哪两种输入？**  
   以现有证据，不应该做全库抽取。若只做对照试验，两种输入都要和同大小的顺序切块一起跑，而不是单独报告：向量 + 实体、上限 8；向量 + 实体、上限 16。试验若不能稳定超过顺序切块，就停止。

10. **不理想的根源是什么？**  
   不是某一条聚类算法没调好。实体重叠、chunk 向量、BM25 和它们的融合，要么得到大社区，要么在切小之后变成局部主题切片。MuSiQue 的支持文档由题目决定，无监督邻域对不齐这些集合。语料文件本身的相邻关系已经解释了顺序基线里的大部分命中。索引阶段的分组路线应停止，不要再进入 Joint Triple Extraction。

## 判断

Can zero-API-cost evidence grouping recover useful cross-document reasoning contexts under a strict indexing-token budget?

不能。严格预算下的最高完整同组覆盖是 31%（1.0×）和 35%（1.5×），顺序切块已经有 23%，随机切块是 0.3%。被分到一起的文档多数不是该题的 gold。继续在 Index-Time 用无监督组代替 Read-Time，预期仍是对局部相似段落做一次更贵的抽取。
