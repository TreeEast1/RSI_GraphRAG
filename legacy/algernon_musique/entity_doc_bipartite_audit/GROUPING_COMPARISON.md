# 分组方法比较

原始连通分量已经说明：只要共享任意一个实体就连边，语料会收成一个分量。这一节比较更严的分组。阈值全部事先列出，没有用 gold 挑选。Gold 出现在最后一节，只做事后覆盖计数。

候选对来自实体到 chunk 的倒排，没有做 11,656² 的两两比较。DF > 50 的实体不进入这条倒排，避免一个高频实体展开成上百万存储对。这个 cap 是计算限制。前面的 union-find 过滤实验仍然使用了包括高频实体在内的全部边。

gpt-4o-mini B1：cap 50 下实际写入 189,569 个不重复 chunk 对，用了 10,365 个实体。另有 151 个 DF > 50 的实体被跳过，它们对应 2,097,989 个“实体–对”槽位。这个数字按每个实体的组合数相加，不是不重复 chunk 对。Luna 是 192,767 对，跳过 146 个实体、1,941,403 个槽位。

在已经写入的对里，gpt-4o-mini 有 92.72% 只共享 1 个 cap 内实体，共享 2 个的 10,523 对，共享 3 个的 2,079 对，共享 4 个及以上的 1,201 对。Luna 的单实体对占 92.20%。因此按共享个数排序和按 IDF 求和排序，在 top-k 上给出几乎相同的聚合统计：多数 chunk 的最近邻就是那一个最高 IDF 的共享实体。加权 Jaccard 会改变邻居，因为它还看两侧实体集合的大小。

## 公式

实体的文档频率记为 df(e)，N = 11,656。

```text
idf(e) = ln((N + 1) / (df(e) + 1))
```

方法 A，共享实体数：两侧都出现、且 df ≤ 50 的实体个数。

方法 B，Shared-IDF Sum：这些共享实体的 idf 之和。

加权 Jaccard：Shared-IDF Sum / (idf(A) + idf(B) − Shared-IDF Sum)。A 和 B 的 idf 质量也只加 df ≤ 50 的实体。df > 50 的实体既不提供连接，也不进入分母。

两种输出：

- 硬聚类：分数达到阈值就连无向边，再取连通分量。一个 chunk 只属于一个组。
- Top-k：每个 chunk 保留分数最高的 k 个邻居，k = 2、4、8、16，组可以重叠。没有 cap 内邻居的 chunk 单独成组，不送进跨 chunk 抽取。

Token 是组内 chunk 的 cl100k 估计之和。预算线用项目里已有的阅读预算 16,000，另看组是否超过 500 个 chunk。

明细：`tables/*_grouping.csv`。Token 曲线：`plots/*_grouping_tokens.png`。

共享至少一个 cap 内实体，等于把 DF > 50 的实体拿掉，最大组仍有 10,637 个 chunk，输入约 127 万 token，必须再拆。IDF 和提到 12 仍然留下 3,551 chunk 的链，因为一条高 IDF 边就可以把组串下去。

共享个数提到 3 以上，或 Jaccard 提到 0.20 以上，最大组才落到几十个 chunk 以内。代价是覆盖急剧下降：Jaccard ≥ 0.20 只覆盖 15.5% 的 chunk，共享个数 ≥ 5 只覆盖 6.5%。落在外面的 chunk 仍要按单篇做抽取。这些小硬组内部重复次数是 1，总阅读量只有全库的 0.16 和 0.09 倍，但它们不是全库分组方案。

Luna 的同一格：Jaccard ≥ 0.20 有 663 组，最大 20 chunk、2,575 token，覆盖 15.9%；共享个数 ≥ 5 最大 26 chunk，覆盖 7.1%。

## 事后的 gold 覆盖

这一节在全部分组算完之后才读 `questions_eval.jsonl`。1,000 道题都有至少两个 gold chunk。Gold 没有回写边，也没有改变上面任何一个阈值。同一分量只表示结构上连得上，不能当成证据组正确率。

gpt-4o-mini B1：

| 结构 | 全部 gold chunk 落在同一组的题数 |
| --- | ---: |
| 原始 NER 分量 | 996 / 1,000 |
| 去掉 DF > 10 | 803 / 1,000 |
| 去掉 DF > 50 | 967 / 1,000 |
| IDF top-2 | 232 / 1,000 |
| IDF top-8 | 390 / 1,000 |
| IDF top-16 | 483 / 1,000 |
| 每对 gold 都共享一个 DF ≤ 50 的实体 | 470 / 1,000 |
| 共享个数 ≥ 3 的硬组 | 48 / 1,000 |
| 共享个数 ≥ 5 的硬组 | 5 / 1,000 |
| Jaccard ≥ 0.20 的硬组 | 32 / 1,000 |
| Jaccard ≥ 0.40 的硬组 | 4 / 1,000 |
| 随机划分，组大小 7 | 0 / 1,000 |
| 按语料顺序切块，组大小 7 | 116 / 1,000 |

原始分量的 996/1,000 来自巨型分量本身。随机组大小 7 的 0/1,000 说明这种覆盖率不是小组随便都能得到的；顺序切块的 116/1,000 里，有一批题的 gold chunk 在语料文件中本身就很近：1,000 题里 216 题的 gold 下标跨度 ≤ 6，跨度中位数是 1,424。顺序基线吃到的是语料排列，不是实体语义。

Luna 的对应数字：原始分量 991/1,000，IDF top-2 是 231/1,000，top-16 是 492/1,000，DF ≤ 50 的直接共享是 488/1,000，Jaccard ≥ 0.20 是 38/1,000。

大约一半的题，其 gold chunk 之间连一个 DF ≤ 50 的共享实体都没有。任何只靠稀有实体重叠的组，结构上到不了这些题。

未进同一原始分量的少数题，gpt-4o-mini 上记为：空 NER 1 题，可能的别名或名称包含 1 题，没有共享 NER 路径 2 题。这是启发式计数，不是错误类型的人工终审。
