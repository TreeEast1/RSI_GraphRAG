# 结论

Entity–Document 二部图可以在三元组抽取之前建出来，但按共享实体求连通分量，不能作为跨文档证据组。HippoRAG 2 的 gpt-4o-mini OpenIE 和 RSI 的 Luna G_raw 给出同一形状。Gold 只在分组固定之后做了覆盖计数，没有用来选阈值，也不能把覆盖率说成分组准确率。

## 七个问题

1. **NER 能形成多少个 chunk 簇？**  
   gpt-4o-mini B1 有 226 个连通分量，Luna B1 有 280 个。其中有意义的大簇只有 1 个。Title 收成节点后，gpt-4o-mini 仍有一个含 9,620 / 9,838 个 title 的分量。

2. **最大、最小和分位数是多少？**  
   gpt-4o-mini B1 最大 11,422 个 chunk，最小 1 个 chunk、0 个实体。未加权中位数、P90、P95 都是 1，P99 是 2。按 chunk 加权后，中位数、P90、P95、P99 都是 11,422。Luna B1 最大 11,365，加权分位数同样等于这个最大分量。未加权中位数描述的是巨型分量外面的孤立点。

3. **有没有巨型分量，由哪些实体造成？**  
   有。gpt-4o-mini B1 的最大分量占 97.99% 的 chunk，B2 占 97.31%。频率最高的是 `United States`、`American`、国家名和年份。拿掉全部 DF > 2% 的 8 个实体后，最大分量仍有 11,334 个 chunk。巨型分量是 DF 2–50 的大量实体织成的，不只是前 50 个泛化名称。

4. **去掉高频实体后改善到什么程度？**  
   最严的预置规则是去掉 DF > 10。最大分量降到 9,028 个 chunk（77.45%），孤立 chunk 升到 17.83%，其中 34 个原本有实体的 chunk 失去全部连接。加权中位数仍是 9,028。分量大小的未加权 P95 是 2。中等簇没有出现。预先规定的“最大分量 ≤ 5%、孤立 ≤ 20%、加权中位数在 2–20”没有一条过滤能达到。Luna 同样没有。

5. **NER 图和三元组实体图差多少？**  
   实体集合差很多，分量结构几乎相同。gpt-4o-mini 有 5,360 个实体只在 NER 中，41,322 个只在三元组端点中。官方 phrase 节点来自三元组端点，计数 102,194，本审计规范化后是 102,050；NER 只有 66,088。B1 最大分量 11,422，B2 是 11,342。多 chunk 分量里只有这个巨型分量被 B2 拆动。`American` 这类 NER 高频词在三元组端点里 DF 只有 43，但国家名和年份在 B2 里仍然很高。

6. **共享个数、稀有实体加权、top-k，哪一种更适合做证据包？**  
   三种都不适合当作全库的跨文档证据包。  
   共享个数 ≥ 1 或较低的 IDF 和，仍留下数千到上万 chunk 的链。  
   共享个数 ≥ 5 或 Jaccard ≥ 0.20 能把最大组压到 26 和 20 个 chunk，组 token 全部低于 16,000，但只覆盖 6.5% 和 15.5% 的 chunk。事后看，全部 gold chunk 落在同一组的题分别是 5/1,000 和 32/1,000。  
   Top-k 的单组很便宜，k = 2 的 token P95 约 690，但每个被覆盖的 chunk 平均进入 2.8 个组，全库要再读约 3.2 遍；k = 16 约 15 遍。事后覆盖是 top-2 的 232/1,000、top-16 的 483/1,000。92.7% 的候选对只共享一个实体，所以共享个数和 IDF 的 top-k 几乎一样。约一半的题，gold chunk 之间没有 DF ≤ 50 的共享实体，稀有实体重叠到不了它们。

7. **下一步最值得验证哪一种输入？**  
   不把任何一种连通分量送去三元组抽取。原始分量和去高频之后的分量都是巨型输入，等于把语料再读一遍。  
   若还要做一次很小的人工核对，对象应是已经算好的 Jaccard ≥ 0.20 硬组：gpt-4o-mini 上 666 组，最大 20 chunk、最大约 2,270 token，总阅读量约全库的 0.16 倍。核对目标是桥接字符串的精度，例如同一人物、出版社、头衔、姓氏和地名是否被当成了同一种关系。这一步仍然不调用抽取模型。它回答不了召回：这套组事后只装下 32/1,000 道题的全部 gold chunk。

## 和原计划的关系

原计划是 NER → 二部图 → 跨文档证据组 → 再抽三元组，从而避免先做完全部 OpenIE、再对图和原文做第二遍阅读。

NER 二部图确实可以只从现成的 NER 缓存建出，也不需要同义词边。它不能把跨文档证据收成可抽取的小组。共享实体在这个语料上首先是国家、年份、头衔、出版社和同形字符串。真正稀有的同一人物桥存在，数量远小于巨型分量。两跳稀有实体还会把转会费和电影版权费、横滨的两场不同决赛串起来。

Jaccard ≥ 0.20 的中等组主要是同一 title 的多个 chunk，或系列页面；Shrek 组会因为票房比较句吃进 Kung Fu Panda。这类组即使抽到三元组，也多半是单篇里已经写明的关系。

因此这一阶段的结果是：在三元组抽取之前用实体–文档重叠来分组，结构上不可行。它没有给第二遍阅读提供一个小而完整的输入。
