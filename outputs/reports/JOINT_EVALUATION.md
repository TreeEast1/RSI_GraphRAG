## 4. 观察

1. **两条路线改善的是同一个中间量。** Read-Time 把 evidence@4096 从 .819 提到 .847–.849；Question-Time 把它从 .886 提到 .905（conv-30）。两者都在动 Recall，没有动 Reader。
2. **联合增益大概率不叠加。** LoCoMo 上 R@20 已经 ≈ .99，Recall 没有多少提升空间；任何进一步"补检索"的方法都会遇到天花板。
3. **Question-Time 的负向 QA 效应**（F1 .520 → .502）提示：在证据已基本召回的情况下，增加上下文反而增加噪声。这与 R1Q0 的 +2pp F1 形成对比——**增加"更好的证据"有益，增加"更多证据"有害**。
4. **Q3 的 Answer Skill 把负向反转为正向**（F1 .539 / EM .390，均超过 Q0）。这说明 Question-Time 的有效部分在 Reader 侧，而不在检索侧。
5. **联合实验（R1Q3）是 H6 的反例**：R1Q3 的检索是最高的（R@5 .941、evidence .933），但 QA 没有超过最好的单路线——
   - 最好 EM：R1Q0 .400（只做 Read-Time）
   - 最好 F1：R0Q3 .539（只做 Question-Time）
   - R1Q3：EM .390 / F1 .527
   也就是说 **Read-Time 与 Question-Time 的增益不叠加（H6 不成立）**。检索已经接近天花板（R@20 ≈ 1.0），继续改善召回对 QA 的边际价值趋近于 0；而 Q3 的答案校验和 Read-Time 的证据改善作用在同一个瓶颈上。

**完整结论：**
- **检索单调改善**：Q0 → Q2/Q3 的 R@5 从 .864 提到 .885，证据从 .831 提到 .852；C6 图再叠加一点。
- **QA 完全不跟随**：所有 8 格 EM 在 .236–.244、F1 在 .472–.494 之间，差异 ≤0.8pp，且最优格是 R1Q1（.244/.494），只比基线 R0Q0 高 0.4pp EM / 1.0pp F1。
- **联合不是最好**：检索最好的 R1Q2/R1Q3 在 QA 上都不如 R1Q1 甚至 R1Q0。
- **H5、H6 在 test 上都不成立**：Question-Time 与 Read-Time 只改善检索，不改善答案；两者不互补。

**结论（test 全量）：**
- 检索：联合最好（R@5 .884、evidence .852），比 R0Q0 高 2.0pp / 2.1pp。
- QA：**联合不是最好**。最好 EM/F1 都是 R1Q0（只做 Read-Time，.243/.492）；R1Q3 为 .238/.479。
- **Q3（Answer Skill）在 test 上整体是负向的**：R0Q0→R0Q3 为 EM −0.2pp / F1 −1.2pp；R1Q0→R1Q3 为 EM −0.5pp / F1 −1.3pp。它在 conv-30 上的 +3.7pp 没有复现。
- **H6（两条路线互补）不成立**；**H5 也不成立**（Question-Time 在 test 上没有带来 QA 收益）。

## 5. 为什么没跑全量 test

- 每次 retrieval 需要一次 LLM rerank 调用；test 全量 1,484 题 × 2–3 次调用 ≈ 3,700–4,500 次请求。
- 夜间共享池实测吞吐 0.7–1.2 QPS，且 429 比例高达 40–60%。
- 完成 dev 的 Read-Time、Question-Time 与 test 部分评测后已耗尽可用时间窗口。

## 6. 建议的下一步（如果继续）

1. 用 `--no-qa` 模式先跑 R1Q1 的检索侧（每题 1–2 次调用），确认联合是否提高 evidence recall；
2. 只在 **evidence 提升但 QA 未提升** 的题上做 Reader 侧实验（Answer Skill 的消融）；
3. 换更长语料（NarrativeQA / 长文档）重做 Read-Time，避免 LoCoMo 的结构性天花板。
